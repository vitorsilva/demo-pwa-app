# Issue 163: OpenAI API Key Validation Fails for Project-Based Keys

**Status:** Resolved
**Date:** January 23, 2026
**Epic:** 11 - Multi-Provider LLM Support
**Discovered:** Manual testing in staging

---

## Problem Statement

When attempting to configure an OpenAI API key in the LLM Providers settings, modern project-based API keys were incorrectly rejected with the error "Invalid API key format. Keys should start with 'sk-'."

---

## Root Cause Analysis

**File:** `src/api/providers-config.js:46`

The regex pattern for validating OpenAI API keys was:
```javascript
keyPattern: /^sk-[a-zA-Z0-9]+$/
```

This pattern did **not** include dashes (`-`) or underscores (`_`), which are valid characters in modern OpenAI project-based API keys. For example:
```
sk-proj-IECUDl2KJ3xt39dcy2-GP1WOKEH8_8w1O9Esr0um0k77JlJsgQqw7xxw0z9npO4h...
        ^                 ^                  ^
      dash              dash            underscore
```

This is the same issue that was fixed for Anthropic keys in Issue #161.

---

## Solution Design

Add dashes and underscores to the character class:
```javascript
// Before
keyPattern: /^sk-[a-zA-Z0-9]+$/

// After
keyPattern: /^sk-[a-zA-Z0-9_-]+$/
```

## Lessons Learned

1. **API key formats evolve** - OpenAI moved from simple `sk-xxx` format to project-based `sk-proj-xxx` format. Regex patterns need to be flexible enough to accommodate these changes.

2. **Pattern consistency across providers** - After fixing Anthropic (Issue #161), we should have proactively checked other providers for similar issues.
