## Problem

Quiz generation fails with "Invalid response format from AI" when the LLM returns a response that cannot be parsed as valid quiz JSON. This accounts for 50% of quiz generation failures (4 out of 8 in telemetry data from Dec 2025 - Jan 2026).

**Telemetry evidence:**

| Date | Topic | Model | Duration |
|------|-------|-------|----------|
| Jan 7 | Verb patterns - gerund/infinitives | deepseek-r1t2-chimera:free | 118s |
| Jan 13 | Estruturas de lewis | deepseek-r1t-chimera:free | 52s |
| Jan 15 | Tenet movie characters/plot | deepseek-r1t-chimera:free | 19s |
| Jan 17 | Area/perimeter formulas | deepseek-r1t-chimera:free | 53s |

**User impact:**
- Quiz generation fails completely
- User must retry manually (may fail again)
- Long wait times (19-118 seconds) before failure
- Frustrating experience, especially on mobile

---

## Root Cause Analysis

### Why does this happen?

1. **DeepSeek R1 "thinking" behavior**
   - DeepSeek R1 models output reasoning/thinking before the answer
   - Response may look like: `<think>Let me create a quiz about...</think>{"questions": [...]}`
   - JSON extractor may fail if it expects pure JSON

2. **Malformed JSON from LLM**
   - Unclosed brackets or quotes
   - Trailing commas (invalid in JSON)
   - Control characters in strings

3. **Schema mismatch**
   - LLM returns valid JSON but wrong structure
   - Missing required fields (questions, options, correctAnswer)
   - Wrong data types

4. **Response truncation**
   - Model hits token limit mid-response
   - JSON is cut off and becomes invalid

### Current behavior

Looking at `src/utils/json-extractor.js`, we already have logic to:
- Find JSON in response text (handles markdown code blocks)
- Clean common issues (trailing commas, control chars)

But it may not handle:
- DeepSeek's `<think>` tags
- Multiple JSON objects in response
- Partial/truncated JSON repair

## Proposed Solution

### Part 1: Improve JSON Extraction

Enhance `src/utils/json-extractor.js` to handle more edge cases:

```javascript
// Step 1: Strip DeepSeek thinking tags (BEFORE other extraction attempts)
text = text.replace(/<think>[\s\S]*?<\/think>/g, '');

// Step 2: Find JSON more aggressively (first { to last })
const firstBrace = text.indexOf('{');
const lastBrace = text.lastIndexOf('}');
if (firstBrace !== -1 && lastBrace > firstBrace) {
  text = text.slice(firstBrace, lastBrace + 1);
}

// Step 3: Clean common JSON issues before parsing
function cleanJSON(text) {
  return text
    .replace(/,(\s*[}\]])/g, '$1')  // Remove trailing commas
    .replace(/[\x00-\x1F]+/g, ' '); // Replace control chars with space
}
```

**Implementation note:** The `<think>` tag removal should happen early in the extraction pipeline, before attempting any JSON parsing.

### Part 2: Add Retry with Different Prompt

If JSON parsing fails, retry once with a stricter prompt. This retry logic lives in `src/api/api.real.js` in the `generateQuestions` function (wrapping lines 119-131):

```javascript
// In generateQuestions(), wrap the parse + validate in retry logic:
let data;
let lastError;

for (let attempt = 1; attempt <= 2; attempt++) {
  const currentPrompt = attempt === 1 ? prompt : `${prompt}

CRITICAL: Respond with ONLY valid JSON. No explanation, no thinking, no markdown. Start your response with { and end with }`;

  try {
    const result = await callOpenRouter(apiKey, currentPrompt, options);
    data = extractJSON(result.text);
    // Validate schema here...
    break; // Success, exit retry loop
  } catch (error) {
    lastError = error;
    if (attempt < 2) {
      logger.warn('Parse failed, retrying with stricter prompt', { attempt });
    }
  }
}

if (!data) throw lastError;
```

**Implementation note:** Only retry on parse/validation failures, not on API errors (rate limit, auth, network).

### Part 3: Schema Validation with Helpful Errors

**Note:** Basic validation already exists in `api.real.js` (lines 128-131) - it checks that `questions` is an array with expected length. This enhancement adds per-question field validation.

Validate parsed JSON against expected schema and provide specific error:

```javascript
function validateQuizSchema(quiz, expectedCount) {
  // Existing validation (already in codebase)
  if (!quiz.questions || !Array.isArray(quiz.questions)) {
    throw new Error('Missing or invalid questions array');
  }
  if (quiz.questions.length !== expectedCount) {
    throw new Error(`Expected ${expectedCount} questions, got ${quiz.questions.length}`);
  }

  // NEW: Per-question field validation
  for (let i = 0; i < quiz.questions.length; i++) {
    const q = quiz.questions[i];
    if (!q.question || typeof q.question !== 'string') {
      throw new Error(`Question ${i + 1}: missing question text`);
    }
    if (!Array.isArray(q.options) || q.options.length !== 4) {
      throw new Error(`Question ${i + 1}: must have exactly 4 options`);
    }
    if (typeof q.correct !== 'number' || q.correct < 0 || q.correct > 3) {
      throw new Error(`Question ${i + 1}: correct must be 0-3`);
    }
  }
  return true;
}
```

**Implementation note:** This function can be extracted to a utility or kept inline in `generateQuestions`.
