# Issue #112: Add 'Screen Name' setting for party mode

**GitHub:** https://github.com/vitorsilva/saberloop/issues/112
**Status:** Open
**Created:** 2026-01-15
**Labels:** enhancement, party-mode
**Branch:** `feat/issue-112-screen-name-setting`

---

## Problem

Users who frequently play party quizzes have to enter their name every time they start or join a session. There's no way to save a preferred display name.

## Proposed Solution

Add a new "Screen Name" setting that stores the user's preferred display name and integrates with the party flow.

### Dependency

> **Prerequisite:** Issue #111 must be completed first (adds host name input to CreatePartyView)

### Behavior

**In Settings:**
- New "Screen Name" field in user preferences
- User can set/update their display name
- Persisted to local storage

**In Party Flow (host or guest):**
- Name input field is pre-filled with the screen name from settings
- User can still modify it for that session if desired
- If setting is empty (first time) and user enters a name:
  - Automatically save that name to the screen name setting
  - Show subtle feedback: "Name saved to settings"

### Benefits
- Reduces friction for repeat users
- First-time users still get prompted
- One-time setup, used everywhere
- User retains control to change per-session if needed

## Implementation Notes

### Session: 2026-01-16

**Completed:**
1. Added `screenName` to DEFAULT_SETTINGS in `settings.js` (default: empty string)
2. Added screen name input as first preference in SettingsView.js
3. Implemented blur-to-save behavior in Settings
4. Added i18n translations to all 9 locale files (en, pt-PT, es, fr, de, it, nl, no, ru)
5. Modified CreatePartyView and JoinPartyView to:
   - Import getSetting/saveSetting from settings.js
   - Prefer screenName setting over partyPlayerName localStorage
   - Track `_screenNameWasEmpty` flag for auto-save behavior
   - Show "Name saved to settings" feedback on first-time auto-save
6. Added unit tests in settings.test.js for screenName
7. Created E2E tests in screen-name.spec.js (6 tests)

**Decisions:**
- Screen name saves on blur (not on every keystroke) to avoid excessive writes
- Auto-save only triggers when screenName was empty at view load
- Feedback message uses the Material Icons checkmark for visual consistency
- Fallback to partyPlayerName localStorage maintains backwards compatibility

**Testing Notes:**
- E2E tests use direct localStorage manipulation for reliable setup
- All 13 unit tests pass, all 6 E2E tests pass
