## Problem

GitHub Actions CI is reporting TypeScript type annotation errors on several files. These are pre-existing issues that need to be resolved.

---

## Affected Files

### src/main.js (line 252)
```
Property 'userAgent' does not exist on type 'never'.
```

### src/core/router.js (line 244)
```
This expression is not constructable.
```

### src/components/ModeToggle.js (line 56)
```
Property 'dataset' does not exist on type 'Element'.
```

### src/api/openrouter-client.js (lines 51, 52, 62, 71, 176)
```
Property 'status' does not exist on type 'Error'.
Property 'response' does not exist on type 'Error'.
```

---

## Root Cause

JSDoc type annotations are incomplete or incorrect, causing TypeScript strict mode checks to fail.

---

## Suggested Fixes

1. **main.js**: Add proper type narrowing for `navigator`
2. **router.js**: Fix ViewClass type definition to be constructable
3. **ModeToggle.js**: Cast `btn` to `HTMLElement` instead of `Element`
4. **openrouter-client.js**: Create a custom error type that includes `status` and `response` properties

## Implementation Notes

### Summary

All TypeScript/JSDoc type annotation errors have been fixed. The original 4 files mentioned in the issue were fixed, plus 2 additional files discovered during typecheck verification.

### Technical Details

1. **main.js**: TypeScript narrows `navigator` to `never` in the else branch of `'serviceWorker' in navigator` because it doesn't understand the type guard. Fixed by adding explicit `Navigator` type assertion.

2. **router.js**: The `Function` type is not constructable. Changed to `new (options?: Object) => Object` which properly represents a constructor function.

3. **ModeToggle.js**: `Element.closest()` returns `Element | null`, but `Element` doesn't have `dataset` (only `HTMLElement` does). Fixed by casting the result to `HTMLElement | null`.

4. **openrouter-client.js**: Standard `Error` type doesn't have `status` or `response` properties. Created `ApiError` typedef extending Error with these optional properties and applied type assertions.

5. **retry.js** (additional): The `isRetryableError` function accessed `error.status` but was typed as `Error`. Created `RetryableError` typedef.

6. **party-session.js** (additional): Object literal `status: 'connected'` was inferred as `string` instead of the specific union type. Added explicit `Participant` type annotation.

### Verification

- `npm run typecheck` passes with no errors
- All 775 unit tests pass
- Production build succeeds
