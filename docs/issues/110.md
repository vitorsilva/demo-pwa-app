## Problem

On the Party Mode results screen, guests see a "Save quiz locally" button, but clicking it does nothing - the functionality is not implemented.

## Proposed Solution

Implement the save functionality so guests can save the quiz they just played to their local IndexedDB storage.

### Behavior
- Guest clicks "Save quiz locally" button
- Quiz data (questions, answers, metadata) is saved to IndexedDB
- Success feedback shown to user
- Button state changes to indicate quiz was saved (disabled or changed text)
- Saved quiz appears in guest's quiz list for future solo play

### Considerations
- Quiz data is already available in memory during party session

### Privacy Decision
**Do NOT store** original creator or party session info when saving. The saved quiz should be treated as a standalone quiz owned by the guest, with no trace back to the party session or original host. This respects user privacy.

### Duplicate Handling
**Check by quiz ID** before saving. If a quiz with the same ID already exists in the guest's local storage (from a previous save or because they created it), do NOT create a duplicate. Instead:
- Show appropriate feedback (e.g., "Quiz already saved")
- Keep the button disabled or change its state

## Acceptance Criteria

- [ ] Guest can click "Save quiz locally" and quiz is persisted to IndexedDB
- [ ] Success feedback is shown after save
- [ ] Button becomes disabled or changes after successful save
- [ ] Saved quiz appears in guest's quiz list
- [ ] Duplicate save is handled gracefully (no duplicate quizzes)
- [ ] Works offline (local storage only)
- [ ] i18n translations added for new UI feedback strings

## Solution Design

### Approach

When guest clicks "Save quiz locally" button:
1. Get quiz data from party session state (already in memory)
2. **Check if quiz ID already exists** in local IndexedDB
3. If exists → show "already saved" feedback, disable button
4. If not exists → strip privacy-sensitive fields, save to IndexedDB
5. Update button state to show success

### Data to Save

Save only the essential quiz data needed for solo play:
- `id` - Quiz identifier (for duplicate detection)
- `topic` - Quiz topic/title
- `questions` - Array of questions with answers
- `createdAt` - Timestamp (set to save time, not original creation)

**Do NOT save:**
- Original creator info
- Party session ID
- Host information
- Any party-related metadata

### Data Flow

```
PartyResultsView.saveBtn.click()
  → Get quiz from partySession.getQuizData()
  → Check if quiz.id exists in IndexedDB
  → IF EXISTS: Show "already saved" feedback
  → IF NOT EXISTS:
      → Strip privacy fields (creator, party info)
      → quizService.saveQuiz(sanitizedQuiz)
      → IndexedDB stores quiz
  → Update UI (disable button, show success)
```

## Implementation Notes

### Session: 2026-01-16

#### Changes Made

1. **db.js** - Added `quizExistsBySourceId(sourceQuizId)` function to check for duplicate quizzes
   - Checks all sessions for matching `sourceQuizId` field
   - Returns `true` if exists, `false` otherwise

2. **quiz-service.js** - Added `quizExists(sourceQuizId)` wrapper function
   - Delegates to `db.js` function
   - Service layer abstraction for views

3. **PartyResultsView.js** - Implemented `_saveLocally()` method
   - Checks for quiz data availability
   - Uses quiz ID for duplicate detection (falls back to generated ID)
   - Checks if quiz already exists before saving
   - Strips privacy-sensitive fields (creator, partySessionId, hostId)
   - Saves sanitized quiz to IndexedDB with `sourceQuizId` field
   - Updates button state: disabled after save, shows success/already saved text
   - Error handling with retry capability

4. **Locale files** - Added translations for all 9 supported languages
   - `party.quizSaved` - Success message
   - `party.quizAlreadySaved` - Duplicate detection message
   - `party.saveFailed` - Error message

5. **E2E Tests** - Added test cases in `tests/e2e/party-mode.spec.js`
   - Tests for save functionality, button state, and duplicate handling
   - Note: Tests require P2P session mocking which is complex

6. **Unit Tests** - Added 4 tests in `src/core/db.test.js`
   - Tests for `quizExistsBySourceId` function

#### Data Structure

  timestamp: number,

}
