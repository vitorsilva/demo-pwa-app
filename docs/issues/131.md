# Issue #131: Grade level on quiz generation screen always shows "middle school" in English

**GitHub:** https://github.com/vitorsilva/saberloop/issues/131
**Status:** Plan Ready
**Created:** 2026-01-16
**Labels:** bug, i18n, ux
**Branch:** `fix/issue-131-grade-level-translation`

---

## Problem

When generating a new quiz, the loading screen displays the grade level always in English ("middle school", "high school", "college") regardless of:
1. The grade level actually selected by the user
2. The user's language setting

**Example from screenshot:**
- User selected: "Ensino Básico" (Portuguese for elementary/basic)
- Loading screen shows: "Nível middle school" (mixing Portuguese "Nível" with English "middle school")

**Expected behavior:**
- If user selected "Ensino Básico", should show "Nível Ensino Básico"
- If user selected "High School" in English, should show "High School Level"

---

## Root Cause Analysis

The bug is caused by storing the raw English grade level value and passing it directly to the i18n template without translation.

**Data Flow:**

1. **TopicInputView.js** - Form uses English values for `<option value="">`:
   ```javascript
   <option value="middle school">${t('topicInput.middleSchool')}</option>
   ```

2. **TopicInputView.js (line 80)** - Extracts the raw value (not displayed text):
   ```javascript
   const gradeLevel = gradeLevelSelect.value || 'middle school';  // Gets "middle school"
   ```

3. **State** - Stores raw English string:
   ```javascript
   state.set('currentGradeLevel', gradeLevel);  // Stores "middle school"
   ```

4. **LoadingView.js (line 71)** - Passes raw string to template:
   ```javascript
   ${t('loading.level', { level: gradeLevel })}
   ```

5. **Translation template** - Just inserts the raw string:
   ```json
   "level": "Nível {{level}}"  // Results in "Nível middle school"
   ```

**The root cause:** The grade level is stored as an internal English identifier but displayed without being translated back to the user's language.

---

## Proposed Solution

**Translate grade level at display time** using a mapping from internal values to i18n keys.

### Implementation

**1. Create grade level translation helper** (`src/utils/grade-level.js` or inline):

```javascript
/**
 * Map internal grade level values to i18n keys
 */
const GRADE_LEVEL_KEYS = {
  'elementary': 'topicInput.elementary',
  'middle school': 'topicInput.middleSchool',
  'high school': 'topicInput.highSchool',
  'college': 'topicInput.college'
};

/**
 * Get translated grade level name
 * @param {string} gradeLevel - Internal grade level value
 * @returns {string} Translated grade level
 */
export function getTranslatedGradeLevel(gradeLevel) {
  const key = GRADE_LEVEL_KEYS[gradeLevel];
  return key ? t(key) : gradeLevel;
}
```

**2. Update LoadingView.js (line 71):**

```javascript
// Before (buggy):
${t('loading.level', { level: gradeLevel || t('topicInput.middleSchool') })}

// After (fixed):
${t('loading.level', { level: getTranslatedGradeLevel(gradeLevel) })}
```

**3. Update other affected locations:**
- `ShareQuizModal.js (line 203)` - Grade level in share card
- Any other UI displaying grade level from stored data

### Why This Approach

- **Minimal change**: Only affects display layer, not storage
- **Backward compatible**: Existing saved quizzes still work (they store English values)
- **API compatible**: OpenRouter prompts still receive English values
- **Centralized**: Single helper function for all grade level translations

### Alternative Considered

**Store i18n key instead of value**: Would require migrating existing data and changing API integration. More invasive for no real benefit.

### E2E Tests

```javascript
test('grade level displays in user language on loading screen', async ({ page }) => {

  // Create new quiz with "Ensino Secundário" (high school)

});
```
