## Problem

When explanation generation fails, users receive generic error messages that don't help them understand or resolve the issue. Telemetry analysis (Jan 2026) revealed three distinct failure modes:

| Error Type | Occurrences | User Impact |
|------------|-------------|-------------|
| Rate limit exceeded | 10 (1 session) | User kept retrying 10x in 2 min, didn't know they hit daily limit |
| Empty response from OpenRouter | 8 (4 sessions) | Transient failures that often work on retry |
| Invalid API key | 1 (1 session) | User didn't know their OAuth token expired |

**Evidence from telemetry:**
- One user hit rate limit and retried 10 times in 2 minutes (session `1767919799277-nodzczm`, Jan 9)
- Empty responses occurred sporadically but often succeed on manual retry
- Invalid API key showed generic failure instead of prompting reconnection

## Root Cause Analysis (Refined After Code Review)

### Current State

**Error detection already exists** in `src/api/openrouter-client.js:129-145`:
```javascript
// Lines 132-144 - already throws specific messages
if (response.status === 401) {
  throw new Error('Invalid API key. Please reconnect with OpenRouter.');
}
if (response.status === 429) {
  throw new Error('Rate limit exceeded. Free tier allows 50 requests/day.');
}
```

**BUT the UI doesn't surface these messages.** In `src/components/ExplanationModal.js:205-231`:
- All errors caught with generic handler
- Shows "Couldn't load personalized feedback" for ALL errors
- No error type detection or specific messages

### 1. Rate Limit Not Communicated

**Current:** `openrouter-client.js` throws "Rate limit exceeded..." but ExplanationModal shows generic error
**Problem:** Good error message exists, UI doesn't use it
**Fix:** Pass error message to UI and display it

### 2. Invalid API Key Not Communicated

**Current:** `openrouter-client.js` throws "Invalid API key..." but ExplanationModal shows generic error
**Problem:** Good error message exists, but no action button to help user
**Fix:** Detect error type and add "Go to Settings" button

### 3. Empty Response Has No Retry

**Current:** `openrouter-client.js:108-110` throws "Empty response" AFTER fetch succeeds
```javascript
// Line 108-110 - this is outside the retry wrapper
if (!text) {
  throw new Error('Empty response from OpenRouter');
}
```
**Problem:** The retry logic wraps the fetch call, but empty response check happens after
**Fix:** Move empty response check inside the retry wrapper

## Implementation Plan

### Part 1: Empty Response Retry (openrouter-client.js)

Move empty response detection inside the retry wrapper so transient failures are automatically retried.

**Before (line 33-86):**
```javascript
const response = await withRetry(async () => {
  const res = await fetch(...);
  if (!res.ok) { /* throw error */ }
  return res;  // Returns Response object
}, options);

const data = await response.json();
const text = extractText(data);
if (!text) throw new Error('Empty response'); // OUTSIDE retry
```

**After:**
```javascript
const result = await withRetry(async () => {
  const res = await fetch(...);
  if (!res.ok) { /* throw error */ }

  const data = await res.json();
  const text = extractText(data);

  // NOW INSIDE retry wrapper
  if (!text) {
    const error = new Error('Empty response from OpenRouter');
    error.status = 503; // Mark as retryable (5xx)
    throw error;
  }

  return { text, data };
}, options);
```

### Part 2: Error Code Classification (openrouter-client.js)

Add `.code` property to errors for reliable detection (string matching is fragile):

```javascript
// In handleApiError function
if (response.status === 401) {
  const error = new Error('Invalid API key. Please reconnect with OpenRouter.');
  error.code = 'INVALID_API_KEY';
  throw error;
}

if (response.status === 429) {
  const error = new Error('Rate limit exceeded. Free tier allows 50 requests/day.');
  error.code = 'RATE_LIMIT';
  throw error;
}
```

### Part 3: Specific Error UI (ExplanationModal.js)

Update error handling in `fetchExplanation` function (lines 148-232):

```javascript
} catch (error) {
  logger.error('Failed to fetch explanation', { error: error.message, code: error.code });

  // Detect error type by code
  if (error.code === 'RATE_LIMIT') {
    showRateLimitError();  // "Daily limit reached..."
  } else if (error.code === 'INVALID_API_KEY') {
    showInvalidKeyError(); // "Connection expired" + Settings button
  } else {
    showGenericError();    // Existing behavior
  }
}
```

### Part 4: i18n Strings (locales/*.json)

Add to `explanation` section in all 9 locale files:

```json
"explanation": {
  "rateLimitError": "Daily limit reached. Free tier allows 50 requests/day. Try again tomorrow.",
  "invalidKeyError": "Your OpenRouter connection expired.",
  "goToSettings": "Reconnect in Settings"
}
```
