## Problem

When explanation generation fails, users receive generic error messages that don't help them understand or resolve the issue. Telemetry analysis (Jan 2026) revealed three distinct failure modes:

| Error Type | Occurrences | User Impact |
|------------|-------------|-------------|
| Rate limit exceeded | 10 (1 session) | User kept retrying 10x in 2 min, didn't know they hit daily limit |
| Empty response from OpenRouter | 8 (4 sessions) | Transient failures that often work on retry |
| Invalid API key | 1 (1 session) | User didn't know their OAuth token expired |

**Evidence from telemetry:**
- One user hit rate limit and retried 10 times in 2 minutes (session `1767919799277-nodzczm`, Jan 9)
- Empty responses occurred sporadically but often succeed on manual retry
- Invalid API key showed generic failure instead of prompting reconnection

---

## Root Cause Analysis

### 1. Rate Limit Not Communicated

**Current behavior:** Generic "Explanation generation failed" error
**Problem:** User doesn't know they hit the 50 req/day free tier limit
**Result:** User keeps retrying, generating more failed requests and frustration

### 2. Invalid API Key Not Communicated

**Current behavior:** Generic "Explanation generation failed" error
**Problem:** User doesn't know their OpenRouter connection expired
**Result:** User can't use explanations until they reconnect, but doesn't know how

### 3. Empty Response Has No Retry

**Current behavior:** Immediate failure on empty response
**Problem:** OpenRouter occasionally returns empty responses (transient issue)
**Result:** User must manually retry, even though automatic retry would likely succeed

---

## Proposed Solution

### Part 1: Specific Error Messages for Rate Limit

**Detect:** `"Rate limit exceeded"` in error message
**Show:** "Daily limit reached. Free tier allows 50 requests/day. Try again tomorrow."
**Optional:** Disable "Explain" button with countdown or suggest upgrading

### Part 2: Specific Error Messages for Invalid API Key

**Detect:** `"Invalid API key"` in error message
**Show:** "Your OpenRouter connection expired. Please reconnect in Settings."
**Action:** Add "Go to Settings" button or link

### Part 3: Automatic Retry for Empty Response

**Detect:** `"Empty response"` error
**Action:** Silently retry up to 2-3 times with 1-2 second delay
**Fallback:** Only show error if all retries fail
**Benefit:** Better UX - user doesn't see transient failures

### Error Detection Logic

```javascript
// Categorize errors from OpenRouter response
function categorizeExplanationError(error) {
  const message = error.message || '';

  if (message.includes('Rate limit exceeded')) {
    return {
      type: 'RATE_LIMIT',
      userMessage: 'Daily limit reached. Free tier allows 50 requests/day. Try again tomorrow.',
      recoverable: false
    };
  }

  if (message.includes('Invalid API key')) {
    return {
      type: 'INVALID_KEY',
      userMessage: 'Your OpenRouter connection expired. Please reconnect in Settings.',
      recoverable: true,
      action: 'settings'
    };
  }

  if (message.includes('Empty response')) {
    return {
      type: 'EMPTY_RESPONSE',
      userMessage: 'Failed to generate explanation. Please try again.',
      recoverable: true,
      shouldRetry: true
    };
  }

  return {
    type: 'UNKNOWN',
    userMessage: 'Explanation generation failed. Please try again.',
    recoverable: true
  };
}
```

### Retry Logic (using existing utility)

```javascript
import { withRetry } from '@/utils/retry.js';

// Wrap explanation call with retry for empty responses
const explanation = await withRetry(
  () => generateExplanation(question, userAnswer, correctAnswer),
  {
    maxRetries: 3,
    delay: 1500,
    shouldRetry: (error) => error.message?.includes('Empty response')
  }
);
```
