## Problem

The Party Mode backend (PHP + MySQL) stores session data for room management and WebRTC signaling. There is currently no automated cleanup process, which means stale/abandoned party sessions accumulate in the database over time.

## Proposed Solution

Configure a cron job on the VPS to periodically clean up old party session data.

### Data to Clean
- Expired/abandoned rooms
- Old signaling messages
- Disconnected peer records
- Any other temporary party session data

### Considerations
- Determine appropriate retention period (e.g., 24 hours? 7 days?)
- Decide on cron frequency (e.g., daily, hourly)
- May need a cleanup script/endpoint in the PHP backend
- Log cleanup operations for monitoring

## Acceptance Criteria

- [ ] Cleanup script/endpoint exists in PHP backend
- [ ] Cron job configured on VPS
- [ ] Stale data is automatically removed on schedule
- [ ] Cleanup is logged for monitoring
- [ ] Active sessions are not affected
- [ ] Documentation updated with cron configuration
