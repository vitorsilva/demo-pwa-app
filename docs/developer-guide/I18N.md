# Internationalization (i18n) Guide

## Overview

Saberloop uses **i18next** for internationalization. The app supports 9 languages with automatic browser language detection and user preference persistence.

```
┌─────────────────────────────────────────────────────────────┐
│                    i18n Architecture                        │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌──────────────────┐      ┌──────────────────────────┐    │
│  │  i18next         │      │  Translation Files       │    │
│  │  (Core library)  │◄────►│  /public/locales/{lang}  │    │
│  └────────┬─────────┘      └──────────────────────────┘    │
│           │                                                 │
│           │  t('key')                                       │
│           ▼                                                 │
│  ┌──────────────────┐      ┌──────────────────────────┐    │
│  │  Views/Components│      │  User Settings           │    │
│  │  (UI Layer)      │◄────►│  (localStorage)          │    │
│  └──────────────────┘      │  - i18nextLng            │    │
│                            └──────────────────────────┘    │
└─────────────────────────────────────────────────────────────┘
```

## Quick Start

### Using Translations in Code

```javascript
import { t } from '../core/i18n.js';

// Simple translation
const text = t('home.welcome');  // "Welcome back!"

// With interpolation
const progress = t('quiz.questionOf', { current: 1, total: 5 });
// "Question 1 of 5"

// Nested keys
const label = t('settings.preferences');  // "Preferences"
```

### Changing Language

```javascript
import { changeLanguage, getCurrentLanguage } from '../core/i18n.js';

// Get current language
const lang = getCurrentLanguage();  // "en"

// Change language
await changeLanguage('pt-PT');

// Subscribe to language changes
import { onLanguageChange } from '../core/i18n.js';

const unsubscribe = onLanguageChange((newLang) => {
  console.log('Language changed to:', newLang);
  // Re-render view
});
```

## Translation File Structure

Translation files are JSON located in `public/locales/{lang}.json`:

```
public/locales/
├── en.json      # English (source of truth)
├── pt-PT.json   # Portuguese
├── es.json      # Spanish
├── fr.json      # French
├── de.json      # German
├── it.json      # Italian
├── nl.json      # Dutch
├── no.json      # Norwegian
└── ru.json      # Russian
```

### Key Namespaces

Keys are organized by feature/section:

```json
{
  "common": {
    "home": "Home",
    "settings": "Settings",
    "save": "Save",
    "cancel": "Cancel"
  },
  "home": {
    "welcome": "Welcome back!",
    "startQuiz": "Start New Quiz"
  },
  "quiz": {
    "questionOf": "Question {{current}} of {{total}}",
    "submitAnswer": "Submit Answer"
  },
  "results": {
    "title": "Results",
    "greatJob": "Great Job!"
  },
  "errors": {
    "network": "Network error. Please check your connection.",
    "generic": "An error occurred. Please try again."
  }
}
```

| Namespace | Description |
|-----------|-------------|
| `common` | Shared UI elements (buttons, navigation) |
| `home` | Home view content |
| `quiz` | Quiz view content |
| `results` | Results view content |
| `settings` | Settings view content |
| `errors` | Error messages |
| `dates` | Date formatting strings |
| `party` | Party mode content |
| `welcome` | Onboarding content |

## Adding New Translation Keys

### 1. Add to English First

Always add new keys to `public/locales/en.json` first (source of truth):

```json
{
  "myFeature": {
    "title": "My Feature",
    "description": "This is a new feature"
  }
}
```

### 2. Use in Code

```javascript
import { t } from '../core/i18n.js';

const title = t('myFeature.title');
const desc = t('myFeature.description');
```

### 3. Run Translation CLI

Translate to all other languages:

```bash
# Set API key (one-time)
# Windows:
set OPENROUTER_API_KEY=sk-or-v1-...

# Linux/Mac:
export OPENROUTER_API_KEY=sk-or-v1-...

# Translate to specific language
npm run translate -- es
npm run translate -- fr
npm run translate -- de
```

### 4. Review Translations

Always review auto-generated translations before committing:
- Check for translation errors
- Verify interpolation variables preserved (`{{variable}}`)
- Test in the app with language selector

## Interpolation

Use `{{variable}}` syntax for dynamic values:

```json
{
  "quiz": {
    "questionOf": "Question {{current}} of {{total}}",
    "score": "You scored {{correct}} out of {{total}}"
  }
}
```

```javascript
t('quiz.questionOf', { current: 3, total: 5 });
// "Question 3 of 5"

t('quiz.score', { correct: 4, total: 5 });
// "You scored 4 out of 5"
```

## Pluralization

i18next handles pluralization automatically:

```json
{
  "dates": {
    "daysAgo_one": "{{count}} day ago",
    "daysAgo_other": "{{count}} days ago"
  }
}
```

```javascript
t('dates.daysAgo', { count: 1 });  // "1 day ago"
t('dates.daysAgo', { count: 5 });  // "5 days ago"
```

## Translation CLI

The CLI tool (`scripts/translate.js`) uses OpenRouter to translate locale files.

### Usage

```bash
# Show help
npm run translate

# Translate to specific language
npm run translate -- es      # Spanish
npm run translate -- fr      # French
npm run translate -- de      # German
npm run translate -- it      # Italian
npm run translate -- nl      # Dutch
npm run translate -- no      # Norwegian
npm run translate -- ru      # Russian
```

### Features

- **Incremental updates**: Only translates new/missing keys
- **Preserves structure**: Keeps JSON structure intact
- **Preserves variables**: Keeps `{{interpolation}}` variables
- **Review required**: Always review before committing

### 4. Test

1. Start dev server: `npm run dev`
2. Go to Settings
3. Select new language
4. Verify all text displays correctly

## Testing with i18n

### E2E Tests

Use `data-testid` attributes instead of text matching:

```javascript
// ❌ Don't do this (breaks with translations)
await expect(page.locator('text=Welcome back!')).toBeVisible();

// ✅ Do this
await expect(page.locator('[data-testid="welcome-heading"]')).toBeVisible();
```

### Unit Tests

For functions that return translated strings, import the translation helper:

```javascript
import { t } from '../core/i18n.js';

// Test the translation key is used correctly
expect(errorMessage).toBe(t('errors.network'));
```

## Core Module Reference

### File: `src/core/i18n.js`

| Export | Type | Description |
|--------|------|-------------|
| `t(key, options)` | Function | Translate a key |
| `changeLanguage(lang)` | Function | Change current language |
| `getCurrentLanguage()` | Function | Get current language code |
| `onLanguageChange(callback)` | Function | Subscribe to language changes |
| `initI18n(options)` | Function | Initialize i18n (auto-called) |
| `isI18nReady()` | Function | Check if initialized |
| `SUPPORTED_LANGUAGES` | Array | List of supported languages |
| `DEFAULT_LANGUAGE` | String | Default language (`'en'`) |

## Troubleshooting

### Translation Key Returns Key Name

```
Expected: "Welcome back!"
Got: "home.welcome"
```

**Cause:** i18n not initialized before `t()` called

**Fix:** Ensure `initI18n()` is called before rendering:
```javascript
import { initI18n } from './core/i18n.js';

await initI18n();
// Now render views
```

---

### Missing Translation Shows English

**Cause:** Key exists in English but not in target language

**Fix:** Run translation CLI:
```bash
npm run translate -- pt-PT
```

---

### Interpolation Not Working

```
Expected: "Question 3 of 5"
Got: "Question {{current}} of {{total}}"
```

**Cause:** Variables not passed to `t()` function

**Fix:** Pass options object:
```javascript
// ❌ Wrong
t('quiz.questionOf');

// ✅ Correct
t('quiz.questionOf', { current: 3, total: 5 });
```

---

### Language Not Persisting

**Cause:** localStorage blocked or cleared

**Fix:** Check browser settings allow localStorage. The language is stored under key `i18nextLng`.

---

### CLI Translation Fails

```
Error: OPENROUTER_API_KEY environment variable not set
```

**Fix:** Set the API key:
```bash
# Windows
set OPENROUTER_API_KEY=sk-or-v1-your-key

# Linux/Mac
export OPENROUTER_API_KEY=sk-or-v1-your-key
```

## Best Practices

1. **Always add keys to English first** - `en.json` is the source of truth
2. **Use meaningful key names** - `settings.preferences` not `s.p`
3. **Group related keys** - Use namespaces like `quiz.`, `results.`, etc.
4. **Preserve interpolation** - Never translate `{{variable}}` parts
5. **Review auto-translations** - LLM translations need human review
6. **Use data-testid in tests** - Don't match on translated text
7. **Test all languages** - Switch languages and verify UI
